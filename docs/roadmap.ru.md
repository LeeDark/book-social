# Дорожная карта

Эта дорожная карта — рабочий ориентир, а не обещание сроков релизов.

## Текущий статус планирования

Канонический источник очередности и принятого scope — `roadmap.md`. Активная версия:
**v0.2.6 Registration/Login/Logout**. v0.2.1–v0.2.5 закрыты; v0.3 и последующие версии остаются
планами. Planning checklist не является подтверждением реализованного поведения: завершение
требует реализации и проверок.

## Принципы планирования

- Каждый релиз должен давать наблюдаемый результат пользователю или оператору, а не только добавлять
  технологии.
- Границы релиза определяет продуктовая ценность; техническая работа её поддерживает.
- Модульный монолит и MPA остаются вариантом по умолчанию, пока измеренные требования не оправдают
  другую архитектуру.
- Доступность, безопасность, тестирование, наблюдаемость, приватность и эксплуатационная готовность
  развиваются с каждым релизом.
- Будущие версии уточняются по результатам разработки, продуктовых метрик и интервью.

## v0.2 — Фундамент каталога и аутентификации

Цель: создать каталог, который можно безопасно изменять, и минимальный фундамент аутентификации для
первого персонального пользовательского цикла.

Основные направления:

- Данные и инфраструктура: проверки качества, миграции, SQLite/PostgreSQL, схема v0.2, репозитории и
  каталог.
- Пользователь: сессии, cookies, регистрация, вход/выход, промежуточные обработчики и интерфейс.

Результат: нормализованный каталог работает через MPA-маршруты; пользователь может
зарегистрироваться, войти, выйти и открыть защищённую страницу; базу можно мигрировать и тестировать
без разрушительных ручных сбросов. Финальная схема личной библиотеки отложена до v0.3.

Критерии готовности:

- [x] Legacy-структуры не выданы за финальную личную библиотеку; обложки — только URL и метаданные.

## v0.3 — Надёжное пользовательское ядро

Цель: превратить каталог с аутентификацией в первый законченный пользовательский продукт.

Путь пользователя: регистрация или вход → выбор книги из курируемого демонстрационного каталога →
добавление в приватную библиотеку → выбор статуса → возвращение к библиотеке.

Подверсии выполняются строго по зависимостям; незакрытый scope не переносится молча в следующую
подверсию.

### v0.3.0 — Фундамент личной библиотеки

  транзакционные границы.
- [ ] Добавить модуль `library`, миграцию `library_items`, уникальность `user_id + book_id` и
  `added_at`.
- [ ] Добавление известной книги и приватная страница `/me/library`.
- [ ] Проверки миграций, repository, гостя, дубля, неизвестной книги и изоляции пользователей на
  SQLite; зафиксировать opt-in PostgreSQL verification path.

Результат: пользователь собирает приватный список «хочу прочитать» из текущего каталога.

### v0.3.1 — Жизненный цикл чтения

- [ ] Статусы `want_to_read`, `reading`, `read` и правила `started_at`/`finished_at`.
- [ ] Состояние текущего пользователя на странице книги, conflict-safe смена статуса и удаление с

Результат: работает полный приватный цикл add → update → return → remove.

## v0.4 — Живой каталог и поиск

одну отсутствующую книгу из контролируемого источника.

Подверсии выполняются по зависимостям: массовый supply v0.5 не начинается до принятия catalog
identity, работающего поиска и первого управляемого импорта v0.4.

### v0.4.0 — Контракт идентичности каталога

- [ ] Принять work/edition, identifiers, languages, provenance, duplicate/merge rules и migration

- [ ] Добавить минимальные schema, repository contracts и operator error/review outcomes.

Результат: поиск и импорт используют устойчивую модель идентичности и исправлений.

### v0.4.1 — Поиск и навигация

Результат: оператор добавляет одну отсутствующую книгу, не делая external API частью обычных

- [ ] Запускать импорт оператором; обеспечить идемпотентность, проверку конфликтов, соблюдение

движок, зависимость обычного каталога от внешнего API, собственное хранилище медиа и микросервисы.

## v0.5 — Платформа поставки каталога и медиа

Цель: масштабировать каталог дальше одного source-specific импортёра, сохраняя явными происхождение
metadata, права, операторский контроль и обработку медиа.

Под публичным массовым импортом здесь понимается операторский импорт общедоступного или
лицензированного каталожного набора с видимым прогрессом и результатом. Это не anonymous endpoint
для произвольных URL и не будущий CSV-импорт личной библиотеки.

Подверсии следуют результатам исследования источников: сначала contracts и rights, затем isolated
pilot, потом reviewed publication и только после этого release closure.

### v0.5.0 — Контракты источников и assets

- [ ] Source registry, shared adapter contract, normalized import record, source-health policy и
  per-field provenance/license model.
- [ ] Asset model/storage boundary: rights/attribution, content validation, hash deduplication,
  local development storage и production storage adapter.

Результат: source и media decisions становятся enforceable data contracts, а не правилами в
import script.

### v0.5.1 — Управляемый batch pilot

- [ ] Shared job lifecycle: dry run, validation report, operator review, idempotent apply,
  pause/resume, bounded retry и audit.
- [ ] Один bounded isolated bulk pilot с accepted source/dataset; измерить quality, duplicates,
  identifiers, languages, rejected rows и review rate.

Результат: batch-import workflow доказан без изменения public catalog.

### v0.5.2 — Reviewed publication и licensed covers

- [ ] Promotion staging records только по явному решению оператора; read-only public progress/result
  с source, version, scope и limitations.
- [ ] Failure isolation, back-pressure и resumability для консистентности repeated/interrupted batch.
- [ ] Хранить и отдавать один класс явно разрешённых cover assets с usage rights и attribution;
  отклонять invalid/unlicensed assets.

Результат: проверенный batch безопасно обогащает public catalog и использует rights-cleared covers.

### v0.5.3 — Закрытие supply chain

- [ ] Tests source admission, batch failure/retry/resume, corrections, media validation и public
  result visibility; security review raw files и external fetches.
- [ ] Документировать source terms, quality/licence evidence, retention, operator procedures и
  метрики принятого источника.

Результат: первый scalable catalog-supply/media path можно сопровождать без заявления о
general-purpose importer или media platform.

### Универсальная основа импорта

- [ ] Реестр источников, контракт source-specific adapter, нормализованная import record, mapping
  полей, provenance, metadata лицензии/использования и policy состояния источника.
- [ ] Общий жизненный цикл job: dry run, validation report, review, idempotent apply, pause/resume,
  retry policy, audit record и публичная read-only страница progress/result.
- [ ] Один production-like массовый adapter только после принятия terms источника, территориальных
  прав, правил обновления и проверки качества; Open Library dump — первый кандидат для оценки, а не
  его low-volume API как backend каталога.
- [ ] Google Books или аналогичные сервисы использовать только для attributed lookup/enrichment по
  явному действию, пока условия не разрешают постоянное массовое хранение данных.
- [ ] Конфликты work/edition, дублей, языка, идентификаторов и metadata показывать оператору; не
  перезаписывать вручную исправленную запись без review.

### Массовый импорт набора данных

- [ ] Bounded pilot import в изолированной среде: измерить покрытие ISBN, дубли, языки, rejected
  records и долю operator review до публикации большего запуска.
- [ ] Публиковать источник, scope, время начала/окончания, версию, агрегированный результат и
  известные ограничения данных каждого принятого batch; raw-source references хранить только если
  это разрешено.
- [ ] Resource limits, resumability, back-pressure, failure isolation и idempotency, чтобы повторный
  или прерванный batch не портил каталог.
- [ ] Не менять публичный каталог при failed import; promotion из staging data требует явного
  решения оператора.

### Начало собственного медиа-хранилища

- [ ] Asset model: hash, media type, dimensions, variants, source, licence/usage proof, attribution,
  lifecycle state и связи с каталогом.
- [ ] Хранить только owned, licensed, public-domain или иным образом явно разрешённые обложки; не
  скачивать массово внешние thumbnails и не hotlink-ить изображения вместо проверки прав.
- [ ] Bounded upload/fetch validation: byte-level type detection, size/dimension limits, image
  decoding, content-addressed deduplication и безопасные ошибки.
- [ ] Небольшая storage boundary: local development storage и production adapter, готовый к object
  storage; без хранения full-text e-books, редактирования изображений и media CDN.

Критерии готовности:

- [ ] Один принятый источник проходит shared job model без логических дублей и с per-field
  provenance.
- [ ] Failed, resumed или repeated batch сохраняет консистентность каталога и имеет audit result.
- [ ] Пользователь видит источник и ограничения опубликованных данных.
- [ ] Приложение хранит и отдаёт только обложки с записанными usage rights и attribution.
- [ ] Риски источника, импорта и медиа покрыты focused tests, operator documentation и
  batch-метриками/логами.

Не входит: scraping защищённых сайтов; third-party API как постоянная database; автоматическое
слияние всех источников без review; anonymous arbitrary-URL import; перенос user reviews/social
data; full-text hosting; универсальная media platform.

## v0.6 — Личная читательская система

Цель: сделать библиотеку причиной регулярно возвращаться и без социального графа.

- [ ] Приватные оценки и заметки.
- [ ] Прогресс чтения, правила дат, повторное чтение и история.
- [ ] Пользовательские полки и теги; поиск, фильтры, сортировка и пагинация библиотеки.
- [ ] Пустые состояния, загрузка, валидация и конфликты.
- [ ] Экспорт данных личной библиотеки.
- [ ] После согласования export contract добавить небольшой authenticated same-origin read-only JSON
  slice `GET /api/v1/me/library/export`: versioned schema, `Cache-Control: no-store`, contract tests
  и точечное согласование с OpenAPI. Не добавлять CORS, bearer tokens или rate limiting без
  конкретной потребности.
- [ ] Один контролируемый импорт личной библиотеки с предварительным просмотром и обработкой
  конфликтов.
- [ ] Серверное соблюдение приватности.
- [ ] Проверить библиотеку на мобильных ширинах и с клавиатурной навигацией.
- [ ] Отделить язык каталога от локали интерфейса.
- [ ] Вынести сообщения интерфейса в стабильные ключи и каталоги переводов.
- [ ] Добавить определение локали, явный выбор, сохранённое предпочтение и запасной язык.
- [ ] Локализовать даты, числа и формы множественного числа; находить отсутствующие ключи в тестах.
- [ ] Измерять активацию, значимую еженедельную активность, удержание W1/W4, прогресс и завершения.
- [ ] Добавить продуктовые панели Grafana и при необходимости Loki/OpenTelemetry.
- [ ] Оставить MPA вариантом по умолчанию; при необходимости проверить один ограниченный компонент
  React.

Критерии готовности:

- [ ] Библиотекой удобно пользоваться при десятках или сотнях книг.
- [ ] Все правила чтения, заметок и тегов имеют тесты.
- [ ] Экспорт работает; импорт идемпотентен и сообщает о конфликтах.
- [ ] Критические запросы измерены и проиндексированы.
- [ ] Панели показывают надёжность, активацию и удержание.

Не входит: социальные ленты, публичные комментарии, полный переход на SPA, машинный перевод
пользовательского контента и обязательный запуск полного стека мониторинга локально.

## v0.7 — Социальное ядро и публичная бета

Цель: создать безопасный социальный цикл и доказать, что Book Social можно эксплуатировать как
публичный сервис.

- [ ] Публичные профили и настройки видимости.
- [ ] Подписка/отписка, списки подписчиков и подписок.
- [ ] Разрешённые виды публичной активности, хронологическая лента без ранжирования и одна реакция —
  лайк.
- [ ] Минимальные уведомления в приложении и публичный отзыв отдельно от приватной заметки.
- [ ] Решить во время реализации, оправдано ли одно same-origin JSON enhancement для идемпотентного
  социального действия реальным пользовательским взаимодействием; MPA-формы остаются baseline, API
  mutation не добавляется ради технологии.
- [ ] Блокировка, жалобы, очередь модерации, ограничения частоты и аудит модерации.
- [ ] Правила сообщества, политика конфиденциальности, условия, контакт поддержки, экспорт и
  удаление данных.
- [ ] Защита от попадания приватных данных в профиль, ленту, события, логи и уведомления.
- [ ] Именованные и версионированные события домена/приложения.
- [ ] Синхронные обработчики внутри процесса; транзакционный outbox и фоновый обработчик только для
  реальных асинхронных задач.
- [ ] Идемпотентные получатели для доставки «как минимум один раз».
- [ ] Не добавлять внешний брокер без измеренной потребности.
- [ ] CI: форматирование, тесты, проверка, линтер, проверка миграций и сборка контейнера.
- [ ] Версионированный артефакт, автоматизированное развёртывание тестовой среды и PostgreSQL-среда,
  близкая к рабочей.
- [ ] Проверки состояния и готовности, безопасные миграции, откат, резервное копирование и
  восстановление.
- [ ] Prometheus/Grafana, Loki, выбранные трассировки OpenTelemetry, alerts и короткая инструкция
  эксплуатации.

Локализация:

- [ ] Подтвердить аудиторию беты до обещания языков.
- [ ] Для двуязычной беты локализовать весь критический путь: аутентификацию, каталог, библиотеку,
  профиль, ленту, жалобы, юридические тексты, уведомления, ошибки и поддержку.
- [ ] Добавить URL каждого языка, канонические URL, hreflang и локализованную карту сайта.

Критерии готовности:

- [ ] Пользователь управляет видимостью, подписывается, видит ленту и оставляет реакцию.
- [ ] Блокировка, жалобы и модерация готовы до публичного доступа.
- [ ] Асинхронные побочные эффекты восстанавливаются после сбоя без дублей.
- [ ] Развёртывание тестовой среды воспроизводимо; откат и восстановление проверены.
- [ ] Панели и alerts показывают здоровье критических путей.
- [ ] Ограниченная бета доступна извне либо имеет документированный внешний блокер запуска.

Не входит: одновременная реализация комментариев, групп и книжных клубов; сложное ранжирование
ленты; Kafka ради демонстрации; gRPC без границы сервиса; полный переход на SPA; инфраструктура
высокой доступности в нескольких регионах.

## v0.8 — Удержание и проверка продукта

Цель: определить, возвращаются ли читатели без постоянных ручных напоминаний, и найти первый
воспроизводимый цикл роста.

- [ ] Провести интервью с бета-пользователями и проанализировать когорты активации и удержания.
- [ ] Улучшить первое знакомство и путь первой книги/первого статуса.
- [ ] Улучшить обратную связь об отсутствующих книгах, импорт каталога и перенос личной библиотеки.
- [ ] Исправить главные причины неудачной активации и оттока.
- [ ] Выбрать ровно одну функцию удержания: цели чтения и статистика, совместное чтение вдвоём или
  один сценарий книжного клуба.
- [ ] Проверить один цикл рекомендаций/поделиться.
- [ ] Проверить один низкорисковый эксперимент: предварительный просмотр, книгу общественного
  достояния или партнёрскую внешнюю ссылку.
- [ ] Улучшить мобильный MPA-опыт и оценить небольшие возможности PWA.
- [ ] Проверить процедуры инцидента, отката, восстановления, модерации, приватности и удаления
  аккаунта.
- [ ] Пересмотреть поддерживаемые локали и необходимость гибридного интерфейса или React по данным.

Критерии готовности:

- [ ] Есть явная гипотеза удержания и условия успеха/неуспеха.
- [ ] Активацию и удержание W1/W4 можно сравнить с v0.7.
- [ ] Выбранная функция оценена с пользователями, а не просто выпущена.
- [ ] Следующая инвестиция выбрана по данным, а не по размеру списка задач.
- [ ] Эксплуатационные процедуры выдерживают рост бета-аудитории.

По умолчанию не входит: полноценная торговая площадка, коммерческая платформа электронных книг,
рабочее пространство автора, письмо с поддержкой ИИ, полная перепись на SPA, брокер, gRPC,
микросервисы и Kubernetes/Helm без эксплуатационной необходимости.

## Явно отложенные направления

- читательские челленджи, серии дней, рекомендации, совместное чтение и книжные клубы;
- дополнительные форматы импорта/экспорта;
- расширенная обработка медиа сверх основы asset storage в v0.5;
- отдельный поисковый движок;
- чтение книг общественного достояния или лицензированных книг;
- партнёрские предложения, платные функции для читателей и эксперименты с монетизацией;
- инструменты автора и письмо с поддержкой ИИ как отдельный продуктовый трек;
- внешний брокер сообщений;
- gRPC после появления реальной границы сервиса;
- выделение сервисов после измеренной потребности в масштабировании, владении, надёжности или
  развёртывании;
- Kubernetes, Helm или конкретная облачная платформа при необходимости для модели развёртывания.
